# ADR-0014：数据许可

- **状态：** accepted（2026-11-06，项目负责人按评审稿建议通过）
- **日期：** 2026-11-06
- **评审人 / 批准人：** 项目负责人
- **规格书出处：** 第 29 节（章节映射见 [../README.md](../README.md)）

## 背景

金融数据的存储、缓存、展示、再分发、向 LLM 发送都可能受合同限制，个人订阅不能默认解释为允许商业使用。

## 候选方案

| 方案 | 说明 | 结论 |
|---|---|---|
| A 不登记 | 由开发者自行把握 | 放弃：合规风险不可控 |
| B 许可注册表 + 默认最小授权 | `provider_entitlements` 记录许可类型、持久化、LLM 传输、再分发、到期时间 | **采纳** |
| C 仅使用免费公开数据 |  | 放弃：覆盖不足 |

## 决定（规格书推荐）

每个 provider 与数据集登记许可；授权不明时默认禁止跨用户、对外展示、再分发、持久化与向 LLM 发送；未完成许可审查的 Provider 不得接入正式环境。

## 理由

- 默认最小授权把合规风险收敛为“显式放开”；
- 与 `retention = hash_only` 联动。

## 后果

- 许可条款的解读需要人完成，不得由 AI 编程智能体判断；
- MVP-2 的 LLM 调用路径必须检查 `llm_transmission_allowed`。

## 测试影响

- `provider_entitlements` 各开关默认 false；
- 持久化未授权时 `raw_payloads.retention` 必须为 `hash_only`。

## 评审结论（2026-11-06）

- **谁有权签署许可审查：** MVP-1 由项目负责人作为唯一签署人；签署记录写入 ADR-0005 与 `provider_entitlements.contract_version`。
- **许可到期后的清除流程：** 到期前由 Scheduler 提醒；到期后自动停止该 Provider 的新拉取，受影响快照标记为不可复现，并在合同规定期限内经受审计的维护流程清除数据。
