# ADR-0017：估值模型适用性与 Pre-flight

- **状态：** accepted（2026-11-06，项目负责人按评审稿建议通过）
- **日期：** 2026-11-06
- **评审人 / 批准人：** 项目负责人
- **规格书出处：** 第 18.0 节（章节映射见 [../README.md](../README.md)）

## 背景

估值引擎面对缺失字段、银行等不适用行业、数学边界（如 WACC ≤ g）时，不能静默补 0，也不能抛出未捕获异常导致 HTTP 500。

## 候选方案

| 方案 | 说明 | 结论 |
|---|---|---|
| A 内部抛异常 | 由调用方处理 | 放弃：产生 500，且不可结构化 |
| B 静默默认值 | 缺失按 0 | 放弃：违反总原则 |
| C 两阶段：Pre-flight → 确定性执行 | 返回 PASS / WARN / BLOCK + 原因码，映射到四种估值状态 | **采纳** |

## 决定（规格书推荐）

Pre-flight 为确定性校验，非 LLM 功能；PASS→`completed`、WARN→`degraded`、BLOCK→`not_applicable` 或 `insufficient_data`，由 `chk_preflight_status_mapping` 约束强制；BLOCK 不返回任何估值数字；行业分类不等于模型适用性。

## 理由

- 调用方可依据原因码决定换模型还是放弃；
- 估值引擎对异常输入永远返回结构化结果。

## 后果

- 原因码分散在 12.6、18.0.3、18.1.3、18.3.1，容易漏改，建议在 Phase 1–3 期间建立统一的原因码注册表（单一事实来源）并版本化；
- 需要按 SIC 维护并版本化的适用性规则表；
- `POST /valuations` 为同步（v1.4）。

## 测试影响

- 第 32 节全部必测案例；
- BLOCK 状态下响应不含估值数字；
- 无输入组合能触发未捕获异常（属性测试）。

## 评审结论（2026-11-06）

- **是否新增统一的原因码注册表：** 同意。新增 [REASON_CODES.md](../REASON_CODES.md) 作为唯一事实来源，代码中对应一个版本化枚举；原因码一经发布不得改名或复用，只能废弃。评审中还发现 API_CONTRACT 25.4 的示例使用 `DATA_REQUIRED_FIELD_MISSING`，与 Pre-flight 的 `MISSING_REQUIRED_FIELD` 含义重复，已统一为后者。
- **银行 / 保险 / REIT 之外是否还需拦截：** 需要。新增证券经纪、基金与封闭式投资公司、空白支票公司（SPAC）。初始清单 `sic_applicability_v1` 见 VALUATION 18.0.3 第 1 条。只拦截 `dcf_fcff` 与 `ev_ebitda`，PE 仍可用。
