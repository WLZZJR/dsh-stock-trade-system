# ADR-0011：原始数据去重与拉取日志分表

- **状态：** accepted（2026-11-06，项目负责人按评审稿建议通过）
- **日期：** 2026-11-06
- **评审人 / 批准人：** 项目负责人
- **规格书出处：** 第 15.2 节、16 节、12.8 节（章节映射见 [../README.md](../README.md)）

## 背景

需要既能回放原始响应，又要保留每一次拉取（含失败与重试）的完整观测历史；同时部分供应商许可不允许保存原始响应。

## 候选方案

| 方案 | 说明 | 结论 |
|---|---|---|
| A 单表 | 每次请求都存完整 payload | 放弃：重复内容占用大 |
| B 分表 | `raw_payloads` 按 (provider, hash) 去重，`ingest_log` 每次拉取一行 | **采纳** |
| C 只存哈希 | 不保存原始内容 | 放弃：无法回放（但作为 `hash_only` 档位保留） |

## 决定（规格书推荐）

`raw_payloads` 去重存储，并带 `retention`（`stored` / `hash_only`）；`ingest_log` 记录每次拉取事件；许可未明确前，该供应商一律 `hash_only`。

## 理由

- 内容去重与事件历史是两个不同关注点；
- `retention` 让“可回放”与“许可约束”可以共存。

## 后果

- `hash_only` 下不能回放，但标准化记录与快照仍可复算；
- 请求参数需脱敏后再计算 `request_hash`。

## 测试影响

- `(provider_id, payload_hash)` 唯一；
- `retention` 与 `payload_json` 空值的 CHECK；
- 失败请求的 `ingest_log` 无 `payload_id`。

## 评审结论（2026-11-06）

- **SEC 公开数据是否一律 `stored`：** 是，`stored`；仍须遵守 SEC fair-access 与 User-Agent 要求。
- **大响应体的存储成本与保留期：** MVP-1 不设自动清理，依赖内容去重与 PostgreSQL 的 TOAST 压缩；Spike S4 记录实际体积，超过部署磁盘预算时再另立保留策略。
