# ADR-0006：WACC 输入规则

- **状态：** accepted（2026-11-06，项目负责人按评审稿建议通过）
- **日期：** 2026-11-06
- **评审人 / 批准人：** 项目负责人
- **规格书出处：** 第 18.1.1 节（章节映射见 [../README.md](../README.md)）

## 背景

DCF 对 WACC 极度敏感。自动推导需要 Beta、风险溢价、无风险利率等数据，其来源、授权与口径在 MVP-1 均未确定；而隐藏默认值会让估值结论不可审计。

## 候选方案

| 方案 | 说明 | 结论 |
|---|---|---|
| A 自动 CAPM 推导 | 由系统取 Beta、ERP 自动计算 | 放弃：数据来源与授权未定，且口径争议大 |
| B 固定默认值 | 如统一 9% | 放弃：隐藏默认值，规格明确禁止 |
| C 用户显式输入并确认 | 作为 `valuation_assumptions` 保存来源、理由与确认状态；缺失或未确认即 BLOCK | **采纳** |
| D 缺省继续但降级 | 缺 WACC 仍输出低置信结果 | 放弃：会产生没有依据的数字 |

## 决定（规格书推荐）

MVP-1 不自动推导 WACC；用户必须显式输入并确认；币种与名义/实际口径须与现金流预测、终值增长率一致；终值增长率必须小于 WACC；MVP-2 的 Agent 只能提出 `agent_suggestion`，未经确认不得生效。

## 理由

- 让最敏感的假设由人负责，系统负责校验与可追溯；
- 不存在隐藏默认值，满足“不静默填默认”的总原则。

## 后果

- 每个研究 Run 都需要预先创建并确认假设（`valuation_assumption_ids`，见 18.1.3），首次使用体验较重；
- 缺失时估值章节进入“不适用与未支持项”，Run 仍可成功；
- 假设版本化追加，已被快照引用的假设不可修改。

## 测试影响

- `WACC_MISSING`、`WACC_UNCONFIRMED`、`WACC_LTE_TERMINAL_GROWTH`、`RATE_BASIS_MISMATCH` 的 Pre-flight 用例；
- 断言代码中不存在任何 WACC 默认值。

## 评审结论（2026-11-06）

- **是否提供 WACC 常见区间提示：** 不提供。避免锚定效应，且参考数据来源未定；用户通过敏感性矩阵观察 WACC 变化的影响。
- **各情景能否使用不同 WACC：** 允许，通过 `valuation_assumptions.scenario` 区分；只有一条 `scenario` 为空的 WACC 时，适用全部情景。
