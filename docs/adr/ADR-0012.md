# ADR-0012：Run / Task 状态机

- **状态：** accepted（2026-11-06，项目负责人按评审稿建议通过）
- **日期：** 2026-11-06
- **评审人 / 批准人：** 项目负责人
- **规格书出处：** 第 22 节（章节映射见 [../README.md](../README.md)）

## 背景

研究是长流程，会失败、重试、被取消，也会因 Worker 崩溃而卡死。对外需要一个简单稳定的标识，内部需要可诊断的子任务状态。

## 候选方案

| 方案 | 说明 | 结论 |
|---|---|---|
| A 单层任务 | 一个任务一个状态 | 放弃：无法表达阶段与重试 |
| B Run + Task 两层 | 对外只暴露 `run_id`；Task 以 `(run, task_type)` 唯一；状态与阶段分离 | **采纳** |
| C 事件溯源 | 全部状态由事件流重建 | 放弃：MVP 过重 |

## 决定（规格书推荐）

Run 状态 `queued/running/succeeded/failed/cancelled`；Task 增加 `retry_wait`、`skipped`；删除 `partial_data`，数据缺失由 `data_quality_status` 与 `skipped` 表达；终止状态不得自动重启。

## 理由

- 状态（status）、阶段（stage）、数据质量三个维度互不混用；
- 可恢复错误走 `retry_wait`，不经 `failed`。

## 后果

- 需要心跳、Reaper 与乐观锁转移守卫；
- `valuation` 阶段内部多个模型的 BLOCK 粒度需明确（v1.4 已规定：全部模型 BLOCK 才整体 `skipped`）；
- `data_collection` 阶段的超时有例外（v1.4）。

## 测试影响

- 状态转移守卫（终态不被覆盖）；
- 僵尸 Run 回收；
- `retry_wait` 期间心跳顺延；
- Clean-before-Write 重试无重复副作用。

## 评审结论（2026-11-06）

- **`data_collection` 默认 15 分钟上限：** 接受作为默认值，可在配置中调整。
- **Reaper 阈值是否可配置：** 可配置：扫描周期默认 60 秒、陈旧阈值默认 5 分钟，均放在 `configs/default.yaml`。
